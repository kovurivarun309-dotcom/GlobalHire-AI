# GlobalHire AI
AI-Powered Global Hiring, Cost Optimization and Workforce Decision Support System.

This academic project combines React + TypeScript, Spring Boot + MySQL, and a FastAPI/scikit-learn ML service. Country seed data is explicitly marked DEMO/SYNTHETIC and is not legal/payroll advice.

## Stack
- Frontend: React, Vite, TypeScript, Tailwind CSS, React Router, Axios, Recharts, Lucide, React Hook Form, Zod
- Backend: Java 17+, Spring Boot, Spring Security, JWT, JPA, MySQL, OpenAPI
- ML: Python, FastAPI, pandas, NumPy, scikit-learn, joblib
- Database: MySQL

## Run
1. Create MySQL database and run `database/schema.sql`, then `database/seed.sql`.
2. Start ML service:
   `cd ml-service && python -m venv .venv && .venv\Scripts\activate && pip install -r requirements.txt && python train_models.py && uvicorn app.main:app --reload --port 8001`
3. Start backend:
   `cd backend && .\mvnw spring-boot:run` (or `mvn spring-boot:run`)
4. Start frontend:
   `cd frontend && npm install && npm run dev`

Default API: http://localhost:8080
ML API: http://localhost:8001
Swagger: http://localhost:8080/swagger-ui.html

Demo accounts created by the application:
- admin@globalhire.local / Admin@123
- hr@globalhire.local / HrManager@123
- user@globalhire.local / User@123

Change these credentials before real deployment.

## Environment
Backend supports `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`, `JWT_SECRET`, `ML_SERVICE_URL`.
Frontend supports `VITE_API_URL`.
ML supports `PORT`.

## Academic note
The ML dataset is synthetic. Metrics shown by the ML service are generated by real train/test evaluation and are not claims about real-world hiring outcomes. Country legal, tax, salary and benefits values in the seed are demonstration values and must be verified against authoritative sources before operational use.


## Legal Documents module (added)
1. Run `database/legal_documents.sql` against the `globalhire_db` database after `database/schema.sql` and `database/seed.sql`.
2. Start the Spring Boot backend and React frontend as usual.
3. Complete the hiring setup to unlock the workspace, then open **Legal Documents** from the left navigation.
4. Search by country, law title or keyword; filter by country and legal category.
5. The read-only APIs are:
   - `GET /api/legal-documents`
   - `GET /api/legal-documents?countryCode=US`
   - `GET /api/legal-documents?countryCode=DE&category=Employment%20and%20Labour`
   - `GET /api/legal-documents/countries`
   - `GET /api/legal-documents/categories`

The initial catalogue contains 173 legal-document references across the 30 countries already in `database/seed.sql`. Each record links to an official legislation portal and is marked `SOURCE_TO_VERIFY`. This is a source-discovery catalogue, not a complete download of every Act or a legally validated rule set. Verify current consolidated text, amendments, effective dates, state/provincial/local variations, collective agreements and applicability before using any item in a hiring decision. The existing decision-support score has not been changed to pretend that these catalogue references are already validated legal-complexity measurements.
